# 足跡 Footprint Sprout

足跡是一款以手機為主的城市散步探索 App。使用者打開 App 後，系統會依照目前定位載入附近真實地點，透過盲盒路線、照片任務、好友連線與 3D 寵物養成，把日常散步變成可累積、可回顧、可共同完成的探索遊戲。

目前線上版本：

- GitHub Pages: https://hotdogfuckingshit.github.io/footprint-sprout-app/
- 專案規則文件: [docs/中技社路線規則邏輯.pdf](docs/%E4%B8%AD%E6%8A%80%E7%A4%BE%E8%B7%AF%E7%B7%9A%E8%A6%8F%E5%89%87%E9%82%8F%E8%BC%AF.pdf)

## 專案定位

本專案不是單純地圖清單，而是「真實城市探索 + 連線陪伴 + 寵物成長」的手機 Web App。

核心設計原則：

- 以手機使用體驗為主，所有主要操作都要能在手機 Safari、Chrome 與社群內建瀏覽器中完成。
- 地點必須來自真實地圖資料，不可虛構店名、景點或公共場所。
- 使用者沒有實際到訪的地點只能觀看，不能留下探索紀錄。
- 路線不直接公布終點，必須完成當前段落任務後才解鎖下一段。
- 寵物養成要綁定真實行走、任務完成、城市到訪與旅程評語。

## 技術架構

- 前端：原生 HTML/CSS/JavaScript，入口檔案為 `index.html`
- 地圖：Google Maps JavaScript API
- 附近地點：Google Places API，後端 API 失敗時可退回瀏覽器端 Places 查詢
- 連線資料：Firebase Authentication + Realtime Database
- 後端服務：`server.mjs` 提供附近地點與 3D 服務代理 API
- Firebase Functions：預留邀請與位置分享推播邏輯
- 測試：Playwright smoke tests，檔案位於 `tests/smoke.spec.js`
- 部署：GitHub Pages，主要分支為 `main`

## 主要功能

### 地圖探索

- 使用者進入 App 後會請求定位並載入附近真實地點。
- 地點範圍以使用者目前位置方圓 500 公尺為主。
- 地圖上最多顯示最近 12 個地點，避免手機卡頓。
- 地點類別包含全部、美食、咖啡、甜點、公園、景點、便利商店、超市。
- 點擊地點卡片可選擇是否跳轉到地圖上查看。
- 地點詳情提供 Google Maps 導航連結。

### 盲盒路線

- 使用者輸入可用時間，範圍為 0 到 120 分鐘。
- 行動條件固定為一般步行。
- 使用者選擇探索主題後，系統依據路線規則產生多段任務。
- 每段只揭露方向、距離、預估步數、預估時間與任務條件。
- 完成照片驗證後才解鎖下一段。
- 完成整趟旅程後可留下評語，評語會提升寵物孵化或進化進度。

### 寵物系統

- 初期使用者擁有一顆寵物蛋，可命名。
- 完成任務、真實到訪、步數累積與旅程評語會推進孵化進度。
- 孵化後寵物會隨機從五種開發者設計好的寵物中抽出。
- 每種寵物都有三個進化型態，進化需求會逐階提高。
- 已解鎖配件可裝備到已孵化寵物上。
- 寵物可在個人頁查看，並支援 3D 旋轉展示。

### 好友與連線

- 使用 Google 登入後可設定使用者名稱與好友碼。
- 可加入好友，查看好友狀態、等級、寵物與今日步數。
- 位置分享必須由使用者選擇指定好友，不能一鍵分享給全部好友。
- 雙方都分享位置後，才計算並顯示彼此距離。
- 好友位置可顯示在地圖上，點擊好友標記可查看距離與大概位置。
- 可建立散步小隊，並獨立邀請指定好友。
- 小隊獎勵可共享，成員加入、退出或隊長解散都要同步更新。

### 使用者狀態與圖鑑

- 左上角顯示使用者名稱與等級。
- 我的頁面顯示使用者等級、經驗值、今日步數、角色外觀、寵物狀態與探索資料。
- 使用者可自訂角色性別、眼睛、眉毛與服裝；儲存後預設鎖定，按編輯後才可再次修改。
- 圖鑑以縣市為單位，點入後顯示已探索過該城市的地點。

## 路線規則邏輯

路線規則參考 `docs/中技社路線規則邏輯.pdf`，目前專案已把規則融合進盲盒路線流程。

### 1. 即時取得真實地點

App 不手動建立假資料庫。路線候選點來自外部地圖 API 回傳的真實 POI，再轉成遊戲地點格式。

目前正式資料來源以 Google Places 為主。文件原始設計也保留 OpenStreetMap / Overpass API 的概念，可作為未來免費備援資料源。

### 2. 類型規則

每個 POI 會先被分類，再依規則決定能不能當任務點、能不能當未知終點、對應哪個探索主題。

| 類型 | 主題 | 可作任務點 | 可作未知終點 | 用途規則 |
| --- | --- | --- | --- | --- |
| 學校 | 建築細節 | 是 | 否 | 只拍外觀或校門意象，不進入校園 |
| 銀行 | 方向參照 | 否 | 否 | 只作方向地標或安全參照 |
| 娛樂地區 | 城市色彩 | 是 | 是 | 觀察招牌、燈光與外觀色彩 |
| 餐廳/美食 | 城市色彩 | 是 | 否 | 觀察招牌設計、文字與氣味聯想 |
| 咖啡廳 | 建築細節 | 是 | 是 | 觀察裝潢、窗景與光影 |
| 市場 | 老街痕跡 | 是 | 否 | 觀察生活痕跡與攤位紋理 |
| 商店/服飾 | 建築細節 | 是 | 否 | 觀察櫥窗陳設與街面材質 |
| 景點/地標 | 全主題 | 是 | 是 | 可作未知終點的公開地標 |
| 車站/公車站 | 回程參照 | 否 | 否 | 不指派任務，只作回程或方向參照 |
| 公園綠地 | 自然縫隙 | 是 | 是 | 觀察植物縫隙與自然光影 |
| 便利商店 | 城市色彩 | 是 | 否 | 觀察日常招牌、入口與街角動線 |
| 超市 | 城市色彩 | 是 | 否 | 觀察入口、標示與人流節奏 |
| 旅館/酒店 | 方向參照 | 否 | 是 | 只作方向地標，不作餐飲或拍照任務 |
| 辦公大樓 | 方向參照 | 否 | 否 | 只作方向參照，不作任務點 |

### 3. 時間換算

使用者輸入的總分鐘數會換算成路線距離預算：

```text
travelBudgetMin = totalMinutes * 0.5
walkSpeedKmH = 4.5
maxRadiusKm = max(0.6, (travelBudgetMin / 60) * walkSpeedKmH)
```

任務段數：

- 0 到 59 分鐘：3 個任務點
- 60 到 119 分鐘：4 個任務點
- 120 分鐘：5 個任務點

### 4. 候選點篩選

候選點必須符合以下條件：

- 是真實地圖 API 回傳的地點。
- 在本次距離預算內。
- 類型規則允許作為任務點。
- 與使用者選擇的探索主題相符，或屬於全主題。
- 避免私人住宅、封閉空間與高風險地點。

如果外部 API 暫時失敗，App 可使用內建安全候選點作為 fallback，但正式資料應優先使用真實地圖 API。

### 5. 加權隨機與路線串接

路線採「加權隨機 + 貪婪串接」：

```text
weight = 1 / (distanceKm + 0.05)
```

離目前段落起點越近，權重越高，但仍保留隨機性，讓每次路線有盲盒感。

每一段的起點是上一段目的地，不是永遠從使用者原點重算。最後一個點會優先從 `landmarkOK = true` 的候選點中挑選，作為未知終點。

### 6. 任務提示與可解釋性

每段任務會產生：

- 前進方向，例如東北、南、西南。
- 方位角，例如約 45 度。
- 距離與預估步數。
- 預估步行時間。
- 抵達判定半徑。
- 該點被選中的規則理由。

範例：

```text
因為在「城市色彩」規則下，距離約 300 公尺內找到「restaurant」類別的真實公共場域；觀察招牌設計、文字與氣味聯想。
```

### 7. 到訪與獎勵限制

- 使用者必須接近任務點，才能完成到訪認證。
- 照片任務在瀏覽器端進行基本清晰度、色彩與紋理檢查。
- 完成旅程後可留下評語。
- 留下評語可提升孵化進度；寵物已孵化時，提升寵物進化進度 0.5%。
- 同一趟旅程只能領取一次評語獎勵。

## 開發與部署

### 安裝

```bash
npm install
```

### 本機開發

```bash
npm run dev
```

預設本機網址：

```text
http://localhost:5173/
```

### 環境變數

Google Maps：

```text
VITE_GOOGLE_MAPS_API_KEY=你的 Google Maps JavaScript API 金鑰
GOOGLE_MAPS_API_KEY=你的 Places API 後端查詢金鑰
```

Firebase：

```text
VITE_FIREBASE_API_KEY=你的 Firebase Web API key
VITE_FIREBASE_AUTH_DOMAIN=你的 authDomain
VITE_FIREBASE_DATABASE_URL=你的 Realtime Database URL
VITE_FIREBASE_PROJECT_ID=你的 projectId
VITE_FIREBASE_MESSAGING_SENDER_ID=你的 messagingSenderId
VITE_FIREBASE_APP_ID=你的 appId
VITE_FIREBASE_VAPID_KEY=你的 Web Push VAPID key
```

3D 服務代理：

```text
MESHY_API_KEY=你的 Meshy API key
```

### 建置

```bash
npm run build
```

### 測試

```bash
npx playwright test --workers=1
```

### Firebase 規則與 Functions

```bash
npm run deploy:rules
npm run deploy:functions
```

如果不升級 Firebase Blaze，離線系統推播與 Cloud Functions 不應作為正式依賴；App 內即時狀態仍可透過 Firebase Authentication 與 Realtime Database 完成。

## 資料與安全

- 位置分享只對使用者指定好友開放。
- 好友距離只有雙方都授權分享後才計算。
- 使用者到訪紀錄、步數、寵物進度與旅程回顧需要寫入使用者自己的 Firebase 節點。
- 不應把私人住宅、封閉空間、銀行、車站等敏感點設計成拍照任務。
- Google Maps API key 必須限制網域，不要把無限制 key 放上公開專案。

## 目前優先修正清單

- 手機 Safari 首次載入地圖需更穩定，不應按定位我後才出現。
- 好友雙向位置分享要避免一方可見、另一方不可見。
- 地圖全螢幕的控制按鈕需固定於 UI 層，不可被地圖縮放或重繪蓋掉。
- 地點分類需持續修正，避免學校、酒店被錯標為美食或甜點。
- 寵物 3D 外型需替換為五種正式設計，並移除舊版球體寵物。
